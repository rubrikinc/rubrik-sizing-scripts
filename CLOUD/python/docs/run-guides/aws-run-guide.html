Run the AWS sizing tool (Python)

Branch master · CLOUD/python/aws · a runbook and command builder. This page does not run anything: it builds commands and a script that you run in your own terminal.

Before you run it The tool is read-only (List/Describe/Get calls). The main files (EC2, volumes, RDS, EFS, DynamoDB, S3, secrets, SQS, KMS, snapshots) were compared with a PowerShell run of the same account and matched. Not run on a real account yet: Cost Explorer, the organization and named-account modes, GovCloud, the SSO device sign-in, the profile modes, recovery points, FSx, Glue and S3 Tables data, and S3 sizes across several storage classes. Start with one account and one region. The CSV files and the JSON hold account IDs, resource names and tags: keep them local, or run with --anonymize (the zip then has no raw JSON; the file that maps labels back stays beside it). Cost Explorer API requests are billed per request (check current AWS pricing); the builder skips cost data by default.

1. Command builder


  
 Run bash run-aws-sizing.sh. It uses the rubrik-sizing-scripts checkout the script sits in, or the one your current folder is in. If there is none, it offers to clone into ./rubrik-sizing-scripts in the folder you run it from (never into your home folder unless you run it there). REPO_DIR=/path bash run-aws-sizing.sh overrides all of this. It then sets up a virtualenv, shows which AWS account you are about to scan, asks you to confirm, and runs the command above.


  
2. Step by step

  
Tick each stage when done (saved in this browser). Do not move on if a stage looks wrong.


  
Stage 0 – Confirm which account you are in 

    
For SSO first run aws sso login --profile <profile>. Make sure the Account ID is the one you intend. The downloaded script also checks the identity the Python tool itself sees: it can differ from this one, for example after aws login.

    
aws sts get-caller-identity


  
Stage 1 – Get the code and install 

    
Python 3.9 or newer. A sparse clone fetches only CLOUD instead of the whole repository. The downloaded script does this for you if ~/rubrik-sizing-scripts is missing. Do not use install.sh (it downloads from a placeholder bucket). The clone below uses the master branch.

    
git clone --depth 1 --filter=blob:none --sparse --branch master \
  https://github.com/rubrikinc/rubrik-sizing-scripts.git ~/rubrik-sizing-scripts
git -C ~/rubrik-sizing-scripts sparse-checkout set CLOUD
cd ~/rubrik-sizing-scripts/CLOUD/python/aws
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python main.py --help


  
Stage 2 – Smallest real run 

    
One region, EC2 and RDS (with their snapshots and AMIs), no cost data. Use the builder above, or:

    
AWS_PROFILE=<profile> python main.py --regions us-east-1 --services ec2,rds --no-cost --output ./output

    
Writes ./output/aws_sizing_results_<timestamp>.zip containing aws_sizing_discovery.json, the PowerShell-style CSV files and output_aws_<timestamp>.log (same names as the PowerShell script).


  
Stage 3 – Inspect the result 

    
unzip -o output/aws_sizing_results_*.zip -d output/last
python3 - <<'PY'
import json, os
path = 'output/last/aws_sizing_discovery.json'
if not os.path.exists(path):
    import glob
    per_account = sorted(glob.glob('output/last/*/aws_sizing_discovery.json'))
    if per_account:
        raise SystemExit('Multi-account zip: one JSON per account folder (%d found). Point path at one of them.' % len(per_account))
    raise SystemExit('No JSON in the zip (an --anonymize run leaves it out); open the CSV files in output/last instead.')
d = json.load(open(path))
print('account       :', d['account_id'])
print('regions       :', d['regions_scanned'])
print('ec2 instances :', len(d['ec2_instances']))
print('ebs attached  :', len(d['ec2_attached_volumes']), ' unattached:', len(d['ec2_unattached_volumes']))
print('rds           :', len(d['rds_instances']))
print('s3 buckets    :', len(d['s3_buckets']))
print('scp suspected :', d['scp_restrictions_suspected'])
print('scan_errors   :', json.dumps(d['scan_errors'], indent=1))
PY

    
This is for a single-account zip. A zip from SSO, org, named-account or profile modes has one <account id>/aws_sizing_discovery.json per account, and the CSV files in it cover all accounts together.

    
Check: the counts match the AWS console for that region; scan_errors is empty (otherwise note the service and error); no docdb or neptune instances in the RDS list. If you can, run the PowerShell script on the same account and compare.


  
Stage 4 – Add S3 

    
S3 sizing makes CloudWatch calls per bucket. Look at size_metric_failed and object_count_metric_failed on each bucket: true means a size of 0 is "unknown", not "empty".

    
AWS_PROFILE=<profile> python main.py --regions us-east-1 --services ec2,rds,s3 --no-cost


  
Stage 5 – All regions, all services 

    
Unreachable or not-enabled regions are skipped quietly by the tool's region probe.

    
AWS_PROFILE=<profile> python main.py --no-cost


  
Stage 6 – Cost data (optional) 

    
Drops --no-cost. Needs ce:GetCostAndUsage. An interactive terminal also asks yes/no for the cost and S3 scans.

    
AWS_PROFILE=<profile> python main.py


  
Stage 7 – Many accounts (only after the single account looks right) 

    
Use the builder's SSO, Organization, named accounts or profile modes. Restrict to a few accounts with the account list first, and tick --preflight-only for a first pass: it signs in to every account, runs only the access check and lists the accounts it could not enter, which also get a sign in row in aws_preflight_check-<timestamp>.csv. Nothing is collected, and it does not touch the progress folder, so the full run afterwards is not affected. With SSO you can skip aws sso login: the tool prints a link and a code and waits for you to sign in. The zip goes to the output directory, next to the downloaded script, as in single-account mode. To combine the CSV files of several runs, run it from the folder above aws (it does not work from inside aws): cd .. && python -m common.consolidate DIR.


  
3. Troubleshooting

  

    
You seeMeaning / what to do

    
The downloaded script says The Python tool cannot use your AWS credentialsThe aws command can sign in in ways the Python library cannot. After aws login, either put temporary credentials in the terminal with eval "$(aws configure export-credentials --format env)" (AWS CLI v2.9 or newer), or run pip install "botocore[crt]" in the tool's virtualenv. Then run the script again.

    
The downloaded script warns that your checkout is behind masterThe script only clones when there is no checkout; it never updates one. Run git -C <the folder it names> pull --ff-only and run it again, or answer y to run the older code anyway. Set SKIP_UPDATE_CHECK=1 to skip the check.

    
Unable to locate credentials or ExpiredTokenNo or expired credentials. Set AWS_PROFILE, export keys, or aws sso login; re-run Stage 0.

    
Cannot sign in to ... skipping in a run of many accountsThe tool could not get into that account (the role is missing or does not trust you, the permission set is not assigned, or a service control policy denies it). The closing box lists every such account, and each has a sign in row with the error code in aws_preflight_check-<timestamp>.csv. Fix them, checking with --preflight-only, then run the same command again.

    
scan_errors with AccessDeniedThe identity lacks a read permission for that service and region. The run continues; add the permission (see below) or skip the service with --services.

    
--anonymize run: where is the mapping back to real names?Beside the zip: aws_anonymized_keys_to_actual_values-<timestamp>.csv and output_aws_not_anonymized_<timestamp>.log. Neither is inside the zip. Keep them local.

    
SSO: "No cached SSO login was found"Run aws sso login, or pass --sso-start-url so the tool signs in itself (it prints a link and a code).

    
scan_errors for cloudwatch mentioning ListMetricsS3 sizes then use only the Standard storage class. Add cloudwatch:ListMetrics to see every class.

    
scp_restrictions_suspected: trueAn organization policy (SCP) explicitly denied a call. Not fixable from the tool; try other regions or ask the account owner.

    
scan_errors entry for cloudwatch with "throttled"CloudWatch rate limit. The tool retries; sizes for those items are unreliable. Re-run later or with fewer regions.

    
A region is missing from the resultsThe region probe skips regions that are not enabled or unreachable. Check output_aws_<timestamp>.log in the zip.

    
Bucket with size_metric_failed: trueThe size lookup failed; a size of 0 means unknown.

Files in the zip
    

      
FileContent

      
aws_sizing_discovery.jsonEverything collected. Left out of an --anonymize zip. In a multi-account zip there is one per account, as <account id>/aws_sizing_discovery.json.

      
output_aws_<stamp>.logThe run log. An --anonymize zip has a one-line note under this name instead.

      
aws_*-<stamp>.csv (26 kinds)The PowerShell-style CSV files, with the same names and columns: aws_ec2_instance_info, aws_ec2_attached_volume_info, aws_ec2_unattached_volume_info, aws_rds_info, aws_efs_info, aws_DynamoDB_info, aws_s3_info, aws_rds_snapshot_info, aws_ebs_and_ami_info, aws_vpc_info, aws_lb_info, aws_route53_info, aws_iam_info, aws_eks_clusters_info, aws_eks_nodegroups_info, aws_kms_numbers, aws_redshift_info, aws_backup_costs, aws_snapshot_storage_costs, aws_fsx_filesystem_info, aws_fsx_volume_info, aws_s3_tables_info, aws_glue_iceberg_info, aws_backup_recovery_points, aws_secrets_numbers, aws_sqs_numbers. A file with no rows is a 0-byte file. In multi-account runs one set covers all accounts.

    

    
The zip is named aws_sizing_results_<yyyy-MM-dd_HHmmss>.zip, like the PowerShell script's. A single-account run leaves only the zip in the output folder. An --anonymize run also leaves aws_anonymized_keys_to_actual_values-<stamp>.csv (maps the labels back) and output_aws_not_anonymized_<stamp>.log: keep those, do not send them.

  
Flags
    

      
--regions a,b / --exclude-regions a,bLimit or skip regions (default: all enabled).

      
--services ec2,rds,...Subset of: backup, dynamodb, ec2, efs, eks, fsx, glue, iac, iam, kms, lb, rds, redshift, route53, s3, s3tables, secrets, sqs, vpc. Leave it out to run everything except iac. Snapshots and AMIs are collected with ec2 and rds unless --no-backup-capacity.

      
--no-backup-capacitySkip RDS snapshots, EBS snapshots and AMIs (like PowerShell's -SkipBackupCapacity).

      
--no-csvWrite only the JSON, not the PowerShell-style CSV files.

      
--preflight-onlyOnly run the access check, in every account of the mode (or the current account), and write aws_access_check_<timestamp>.zip with aws_preflight_check-<timestamp>.csv and the log. Nothing is collected and no progress folder is used. Accounts that cannot be signed in to get a sign in row and are listed at the end. Not with --no-csv; without --no-cost it makes one billed Cost Explorer request per account.

      
--keep-artifactsSingle-account mode: also leave the loose JSON and CSV files beside the zip. By default only the zip is left, as with Azure and GCP. With --anonymize the loose JSON holds the real names. The multi-account modes write only the zip and ignore it.

      
--all-profiles / --profiles a,b / --profile-location FILEScan the account of every local profile, or only the named ones, reading profiles from another credentials file (PowerShell's -AllLocalProfiles, -UserSpecifiedProfileNames, -ProfileLocation).

      
--cross-account-role NAME --accounts a,b (or --accounts-file FILE)Scan the named accounts through an IAM role, without calling Organizations (PowerShell's -CrossAccountRoleName).

      
--org --role-name NAME (alias --org-role-name) [--accounts a,b]All accounts of the organization, or only the listed ones, through this role. The default is RubrikDiscoveryRole; PowerShell's default is OrganizationAccountAccessRole.

      
--sso --sso-start-url URL --sso-region REGION [--role-name NAME] [--accounts a,b]Scan through IAM Identity Center, all accounts or the listed ones, with this permission set. Signs in with a device link if aws sso login was not run. The region defaults to the cached login's, else us-east-1.

      
--partition govcloud / --region-to-query REGIONScan GovCloud (account-wide calls use us-gov-east-1; Cost Explorer is skipped), or choose the region for STS, IAM and Organizations calls.

      
--anonymize [--anonymize-fields a,b] [--not-anonymize-fields a,b]Replace names, ids and tags in the CSV files with labels. The zip then has no raw JSON; the file that maps labels back to real values and the real log are written beside the zip, not inside it. Tags in --not-anonymize-fields leaves all tag columns alone.

      
cd .. && python -m common.consolidate DIRRun from the folder above aws. Combine the CSV files of several runs into one <prefix>_combined.csv per kind (PowerShell's consolidate.ps1).

      
--bucket NAME [--bucket-region REGION]Also upload the results to this S3 bucket (default region us-east-1). Needs s3:PutObject on it. Optional; the zip is always written locally.

      
--no-cost / --no-capacitySkip Cost Explorer / skip S3 sizing (drops the S3 collector).

      
--assume-role ARNAssume a role before scanning.

      
--output DIR, --workers N, --verboseFolder for the zip, the run log and the progress folder (default: ./outputs for one account, the current folder for several); accounts in parallel; debug logging.

    

  
The PowerShell scripts remain the reference for output files and sizing rules. Python parameter mapping: CLOUD/python/docs/powershell-parameter-mapping.md.
