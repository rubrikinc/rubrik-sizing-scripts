Run the GCP sizing tool (Python)

Branch master · CLOUD/python/gcp · a runbook and command builder. This page does not run anything: it builds commands and a script that you run in your own terminal or Google Cloud Shell.

Before you run it The tool only reads (list and get calls). It has not been run on a real GCP project yet. The VM, disk, Cloud SQL, Spanner and BigQuery CSV files, and their anonymization, were compared with the PowerShell script's own code on the same inputs, with gcloud and bq replaced by test data. No call to the real BigQuery API has been made yet. The Cloud Asset, AlloyDB and Bigtable parts, --org and --security were not compared with anything. Start with one project and send back anything that looks wrong. With no scope option the tool scans every project the credentials can see. The builder's default is the current project only. The zip holds project IDs, resource names and labels. Keep it local, or run with --anonymize (the zip then has no raw JSON; the file that maps the labels back to the real names stays beside it).

1. Command builder


  
 Run bash run-gcp-sizing.sh. It uses the rubrik-sizing-scripts checkout the script sits in, or the one your current folder is in. If there is none, it offers to clone into ./rubrik-sizing-scripts in the folder you run it from. REPO_DIR=/path bash run-gcp-sizing.sh overrides all of this. It then sets up a virtualenv, checks that Application Default Credentials work, shows the project and account, asks you to confirm, and runs the command above.


  
2. Step by step

  
Tick each stage when done (saved in this browser). Do not move on if a stage looks wrong.


  
Stage 0 – Sign in and confirm the project 

    
The tool uses Application Default Credentials, which are separate from gcloud auth login. Locally run gcloud auth application-default login; in Cloud Shell they already exist. Then check the project it will use. Output is hidden for the token check on purpose.

    
gcloud auth application-default login
gcloud auth application-default print-access-token >/dev/null && echo "ADC works"
gcloud config get-value project
gcloud auth list --filter=status:ACTIVE --format="value(account)"


  
Stage 1 – Get the code and install 

    
Python 3.10 or newer. A sparse clone fetches only CLOUD. The downloaded script does this for you. run.sh in the gcp folder downloads a Rubrik-hosted wheel with a signed link and is not used here.

    
git clone --depth 1 --filter=blob:none --sparse --branch master \
  https://github.com/rubrikinc/rubrik-sizing-scripts.git ~/rubrik-sizing-scripts
git -C ~/rubrik-sizing-scripts sparse-checkout set CLOUD
cd ~/rubrik-sizing-scripts/CLOUD/python/gcp
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python main.py --help


  
Stage 2 – Try it with sample data (no credentials) 

    
Proves the install works and shows the output files. Nothing is sent to Google.

    
python main.py --mock --output ./output

    
Writes ./output/gcp_sizing_results_<yyyy-MM-dd_HHmmss>.zip. The sample data has counts but no individual VMs, disks or databases, so those CSV files are empty. The BigQuery file has two sample rows.


  
Stage 3 – Smallest real run 

    
Only the project from Stage 0:

    
python main.py --current-project --output ./output

    
Writes ./output/gcp_sizing_results_<timestamp>.zip: gcp-sizing-discovery-<timestamp>.json, the six PowerShell-style CSV files, and output_gcp_<timestamp>.log.


  
Stage 4 – Inspect the result 

    
unzip -o output/gcp_sizing_results_*.zip -d output/last
python3 - <<'PY'
import glob, json
paths = glob.glob('output/last/gcp-sizing-discovery-*.json')
if not paths:
    raise SystemExit('No JSON in the zip (an --anonymize run leaves it out); open the CSV files in output/last instead.')
d = json.load(open(paths[0]))
total = lambda key, field: sum(p.get(field, 0) for p in d.get(key, []))
print('projects      :', len(d['projects_scanned']))
print('regions       :', d['regions_in_scope'] or 'all')
print('vm instances  :', total('compute', 'total_instances'))
print('unattached dsk:', total('compute', 'total_unattached_disks'))
print('buckets       :', total('storage', 'total_buckets'))
print('databases     :', total('databases', 'total_databases'))
print('bigquery      :', total('bigquery', 'dataset_count'), 'datasets,', sum(len(p.get('tables', [])) for p in d.get('bigquery', [])), 'tables and views')
posture = d.get('backup_posture', [])
known = [p for p in posture if p.get('available', True)]
print('protected     :', sum(p['protected_instance_count'] for p in known), ' unprotected:', sum(p['unprotected_instance_count'] for p in known), ' (backup coverage n/a in', len(posture) - len(known), 'project(s))')
print('errors        :', json.dumps(d['collection_errors'], indent=1))
PY
ls -l output/last/*.csv

    
Check: the counts match the Cloud console for that project; errors is empty (otherwise note the collector and the message: a disabled API or a missing role). A project the tool could not fully read shows as zeros and under-counts, and the tool prints a yellow warning about it. Backup coverage shown as n/a (available: false in the JSON) means Backup and DR could not be read, which is not the same as 0%. A CSV file with no rows is a 0-byte file (that is what PowerShell does too). If you can, run Get-GCPSizingInfo.ps1 on the same project and compare.


  
Stage 5 – Several projects 

    
Use These projects or a project file with two or three projects first. Each project needs the roles below.


  
Stage 6 – Everything you can see 

    
--all scans every accessible project. For a large organization add --org <id> (one asset sweep instead of a call per project) and raise --workers.

    
python main.py --all --org <org id> --workers 16 --output ./output


  
Stage 7 – Anonymized run (when the files must leave your hands) 

    
Tick --anonymize in the builder. Besides the zip you get gcp_anonymized_keys_to_actual_values-<timestamp>.csv and output_gcp_not_anonymized_<timestamp>.log beside it. They hold the real names: keep them, do not send them.


  
3. Troubleshooting

  

    
You seeMeaning / what to do

    
An authentication error panel, or DefaultCredentialsErrorNo Application Default Credentials. Run gcloud auth application-default login (in Cloud Shell, reopen it). gcloud auth login alone is not enough. Or set GOOGLE_APPLICATION_CREDENTIALS to a service account key file.

    
PERMISSION_DENIED or 403 for a collectorThe identity lacks the role for it (table below). The run continues; the failure is in collection_errors. Grant the role, or limit --collectors.

    
Project ... not accessible: ... — skippingThe sign-in cannot read that project (no role on it, another organization, or a typo: both look the same). It is left out, listed at the end of the run, and has a project row with the error code in gcp_preflight_check-<timestamp>.csv. Tick --preflight-only to check a list of IDs without scanning.

    
SERVICE_DISABLED or "API has not been used in project"Enable that API in the project, for example gcloud services enable compute.googleapis.com --project <id>, and re-run. Enabling an API changes the project, so ask the owner first.

    
Protected shows n/a for a projectBackup and DR could not be read: its API is disabled or the identity lacks roles/backupdr.viewer. The reason is in collection_errors (collector backup). The project is left out of the Protected total, and the JSON still lists its VMs as unprotected with available: false.

    
collection_errors has a bigquery record that ends in "(N table details calls failed)" or similarSome BigQuery calls failed (no permission on a dataset or table, or the API is off), so the BigQuery totals may be low. One record is written per kind of failure, with the number of calls. Grant roles/bigquery.metadataViewer or enable the BigQuery API.

    
A project with very many BigQuery tables takes a long timeBigQuery is read with one call per table. Untick bigquery in the builder (or leave it out of --collectors) to skip it. The file is then still written, empty.

    
Many projects scanned that you did not mean toYou left the scope at Every project I can see. Use Current project only or --projects.

    
Fewer projects than expectedThe identity cannot see them. Check gcloud projects list with the same account, and that Resource Manager access exists.

    
--security returns nothing or failsIt needs roles/securitycenter.findingsViewer at the organization level.

    
--anonymize run: where is the mapping back to real names?Beside the zip: gcp_anonymized_keys_to_actual_values-<timestamp>.csv and output_gcp_not_anonymized_<timestamp>.log. Neither is inside the zip.

    
--anonymize-fields needs --anonymize, or --anonymize cannot be used with --no-csvTick --anonymize; anonymizing works on the CSV files.

    
ModuleNotFoundError for a google.* packageThe virtualenv is not active or the install did not finish. source .venv/bin/activate, then pip install -r requirements.txt.

Grant them at the organization or folder, or on each project. The APIs behind these (Cloud Asset, Compute, Cloud Storage, Cloud SQL Admin, Spanner, AlloyDB, Bigtable Admin, BigQuery, Backup and DR, Resource Manager) must be enabled in the projects. The Cloud SQL database count also lists databases; whether roles/cloudsql.viewer allows that has not been checked on a real project.

  
Files in the zip
    

      
FileContent

      
gce_vm_info-<stamp>.csvVMs

      
gce_attached_disk_info-<stamp>.csvDisks attached to a VM

      
gce_unattached_disk_info-<stamp>.csvDisks with no VM

      
gce_cloudsql_info-<stamp>.csvCloud SQL instances

      
gce_spanner_info-<stamp>.csvSpanner instances

      
gce_bigquery_info-<stamp>.csvBigQuery tables, views, materialized views, external tables and snapshots, one row each

      
gcp-sizing-discovery-<stamp>.json, output_gcp_<stamp>.logEverything collected (including buckets, AlloyDB, Bigtable, Backup and DR); the log. The JSON is left out of an --anonymize zip.

    

    
The zip is named gcp_sizing_results_<yyyy-MM-dd_HHmmss>.zip, like the PowerShell script's. Buckets, AlloyDB, Bigtable and Backup and DR are in the JSON only; the PowerShell script has no files for them.

    
Sizes. Google counts a Compute Engine disk's sizeGb in binary gigabytes (1 GB is 2^30 bytes), so it is really GiB. In the disk and VM files SizeGb is that number. SizeTb and the VM totals are the same number divided by 1000, exactly as the PowerShell script writes them: neither TB nor TiB. SizeGiB and SizeTiB (the same number divided by 1024) are the exact figures. In the BigQuery file the sizes come from bytes: Gb and Tb are decimal (10^9 and 10^12 bytes), GiB and TiB binary. The unit of the Cloud SQL sizes has not been verified.

  
Flags
    

      
--current-project / --projects a,b / --project-file FILE / --allScope; pick one. With none, every accessible project.

      
--org ID / --folder IDUse the org-wide (or folder-wide) Cloud Asset sweep to find assets for all projects at once.

      
--regions a,b, --workers NLimit regions (default: all); projects in parallel (default 8).

      
--collectors a,b / --inventory-onlySubset of asset,compute,storage,database,bigquery,backup (default all, BigQuery included); or only the asset spine. Not combinable.

      
--securitySecurity Command Center findings (organization-level role).

      
--anonymize [--anonymize-fields a,b] [--not-anonymize-fields a,b]Replace names, IDs and labels in the CSV files with labels. By default that includes the BigQuery DatasetId, TableId and ExternalSourceUri. Tags in --not-anonymize-fields leaves label columns alone. Not combinable with --no-csv.

      
--no-csvWrite only the JSON.

      
--preflight-onlyOnly run the access check in each project and write gcp_access_check_<timestamp>.zip with gcp_preflight_check-<timestamp>.csv and the log. Nothing is collected. A project named with --projects that cannot be read gets a project row. Not with --no-csv or --mock.

      
--output DIR, --verbose, --mock, --dry-run, --config FILEOutput directory (default ./output); extra output; sample data; print scope and the calls it would make, then exit; settings file (flags win).

    

  
The PowerShell script Get-GCPSizingInfo.ps1 remains the reference for output files. Flag mapping: docs/powershell-parameter-mapping.md.
