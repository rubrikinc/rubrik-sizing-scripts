Run the Azure sizing tool (Python)

Branch master · CLOUD/python/azure · a runbook and command builder. This page does not run anything: it builds commands and a script that you run in your own terminal or Azure Cloud Shell.

Before you run it The tool only reads (list and get calls). It has not been run on a real Azure tenant yet. Its CSV files were compared with the PowerShell script's own row-building code on the same inputs, with the Azure calls replaced by test data, and matched except for a few known differences. Expect surprises on a real tenant: start with one subscription, --no-cost and --no-devops, and send back anything that looks wrong. The zip holds subscription IDs, resource names and tags. Keep it local, or run with --anonymize (the zip then has no raw JSON; the file that maps the labels back to the real names stays beside it). Known problem on this branch: --dry-run and --manifest fail with No module named 'audit_manifest' (that file arrives with another pull request). Do not use them yet. --mock works and needs no credentials.

1. Command builder


  
 Run bash run-azure-sizing.sh. It uses the rubrik-sizing-scripts checkout the script sits in, or the one your current folder is in. If there is none, it offers to clone into ./rubrik-sizing-scripts in the folder you run it from. REPO_DIR=/path bash run-azure-sizing.sh overrides all of this. It then sets up a virtualenv, shows which subscription you are about to scan, asks you to confirm, and runs the command above. You must already be signed in (az login); in Azure Cloud Shell you are.


  
2. Step by step

  
Tick each stage when done (saved in this browser). Do not move on if a stage looks wrong.


  
Stage 0 – Confirm which subscription you are in 

    
Run az login first (not needed in Cloud Shell). Without --subs or --all the tool scans the subscription shown here, so make sure it is the one you intend. For a Government cloud first run az cloud set --name AzureUSGovernment.

    
az account show --query "{name:name, id:id, tenant:tenantId, cloud:environmentName}" -o table


  
Stage 1 – Get the code and install 

    
Python 3.10 or newer. A sparse clone fetches only CLOUD. The downloaded script does this for you. There is no installable package for Azure yet, so run python main.py from the azure folder; run.sh in that folder downloads from a Rubrik storage account and is not used here. requirements.txt also lists test and build tools, so the install is bigger than the tool needs.

    
git clone --depth 1 --filter=blob:none --sparse --branch master \
  https://github.com/rubrikinc/rubrik-sizing-scripts.git ~/rubrik-sizing-scripts
git -C ~/rubrik-sizing-scripts sparse-checkout set CLOUD
cd ~/rubrik-sizing-scripts/CLOUD/python/azure
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python main.py --help


  
Stage 2 – Try it with sample data (no credentials) 

    
Proves the install works and shows the output files. Nothing is sent to Azure.

    
python main.py --mock --output ./output

    
Writes ./output/azure_sizing_results_<yyyy-MM-dd_HHmm>.zip with the sample data's CSV files and a log.


  
Stage 3 – Smallest real run 

    
The subscription you are logged in to, no cost data, no DevOps. Use the builder above, or:

    
python main.py --no-cost --no-devops --output ./output

    
Writes ./output/azure_sizing_results_<timestamp>.zip: rubrik-discovery-<timestamp>.json, the PowerShell-style CSV files, and output_azure_<timestamp>.log.


  
Stage 4 – Inspect the result 

    
unzip -o output/azure_sizing_results_*.zip -d output/last
python3 - <<'PY'
import glob, json
paths = glob.glob('output/last/rubrik-discovery-*.json')
if not paths:
    raise SystemExit('No JSON in the zip (an --anonymize run leaves it out); open the CSV files in output/last instead.')
d = json.load(open(paths[0]))
print('subscriptions :', len(d['subscriptions']))
print('regions       :', d['regions_in_scope'] or 'all')
print('vms           :', d['total_vms'], ' disk TB:', d['total_disk_tb'])
print('protected vms :', d['total_protected_vms'], ' unprotected:', d['total_unprotected_vms'])
print('storage accts :', d['total_storage_accounts'], ' GB:', d['total_storage_gb'])
print('sql databases :', d['total_sql_databases'], ' managed instances:', d['total_sql_mi_instances'])
print('aks / cosmos  :', d['total_aks_clusters'], '/', d['total_cosmos_accounts'])
print('skipped       :', d['skipped'])
PY
ls -l output/last/*.csv

    
Check: the counts match the Azure portal for that subscription; the log has no 403 or AuthorizationFailed lines (see Troubleshooting); a CSV file with no rows is a 0-byte file (that is what PowerShell does too). The JSON has no list of errors, so look in the log for collector failures. If you can, run Get-AzureSizingInfo.ps1 on the same subscription and compare.


  
Stage 5 – Add cost data and DevOps 

    
Drops --no-cost and --no-devops. Cost needs Cost Management Reader; Azure throttles that API, so the tool retries and the run can take longer. DevOps discovery contacts dev.azure.com for every organization your identity belongs to; limit it with --devops-orgs.

    
python main.py --output ./output


  
Stage 6 – More subscriptions (only after one looks right) 

    
Use the builder's These subscriptions or Every enabled subscription. Try two subscriptions first. The identity needs Reader on each.


  
Stage 7 – Anonymized run (when the files must leave your hands) 

    
Tick --anonymize in the builder. Besides the zip you get azure_anonymized_keys_to_actual_values-<timestamp>.csv and output_azure_not_anonymized_<timestamp>.log beside it. They hold the real names: keep them, do not send them.


  
3. Troubleshooting

  

    
You seeMeaning / what to do

    
An authentication error panel, or DefaultAzureCredential failedNot signed in or the token expired. Run az login (in Cloud Shell, reopen it) and run Stage 0 again. A service principal needs AZURE_CLIENT_ID, AZURE_TENANT_ID and a secret or certificate in the environment.

    
Zero VMs, disks or accounts, no errorUsually the wrong subscription (Stage 0) or no Reader role on it. Check the portal's Access control (IAM).

    
Subscription ... not accessible: ... — skippingThe sign-in cannot read that subscription (no role on it, another tenant, or a typo: both look the same). It is left out, listed at the end of the run, and has a subscription row with the error code in azure_preflight_check-<timestamp>.csv. Tick --preflight-only to check a list of IDs without scanning.

    
Log lines with 403 or AuthorizationFailedA missing role for that part: Cost Management Reader (cost), Monitoring Reader or Reader (storage metrics), Security Reader (Defender, which returns empty on 403). The run continues; add the role or skip that part.

    
Cost data missing, "throttled" or 429Cost Management rate limit. The tool retries a few times. Re-run later or with --no-cost.

    
Government or China tenant finds nothingUse --cloud AzureUSGovernment (or set AZURE_CLOUD). The default is detected from az cloud show.

    
No module named 'audit_manifest'You used --dry-run or --manifest. Known problem on this branch; leave them out.

    
--anonymize run: where is the mapping back to real names?Beside the zip: azure_anonymized_keys_to_actual_values-<timestamp>.csv and output_azure_not_anonymized_<timestamp>.log. Neither is inside the zip.

    
--anonymize-fields needs --anonymize, or --anonymize cannot be combined with --no-csvTick --anonymize; anonymizing works on the CSV files.

    
azure-mgmt-dataprotection is not installed, or a yellow line saying Backup Vaults will not be reportedThe tool's environment is missing a package from requirements.txt. Run the generated script again (it installs requirements.txt), or run pip install -r requirements.txt in the azure folder with its .venv active. Until then the three Backup Vault files are not written and Blob and PostgreSQL backup shows as not protected.

    
ModuleNotFoundError for an azure.* packageThe virtualenv is not active or the install did not finish. source .venv/bin/activate, then pip install -r requirements.txt.

  


  
4. Reference

  
Roles the tool uses (read-only)
    

      
RoleScopeFor

      
Readereach subscriptionEverything inventoried: VMs, disks, storage accounts, SQL, PostgreSQL, vaults (Recovery Services and Backup Vaults), AKS, Cosmos DB, and, unless a narrower role is given, storage metrics.

      
Cost Management Readereach subscription6-month spend and backup costs (skip with --no-cost).

      
Monitoring Reader (or Reader)each subscriptionStorage used capacity and object counts (skip with --no-capacity).

      
Security Readereach subscriptionDefender plans (skip with --no-security).

      
Member of the Azure DevOps organizationeach orgRepository discovery (skip with --no-devops).

    

    
The tool's help refers to a least-privilege custom role file (docs/rubrik-discovery-reader-role.json); it is not in the repository yet. For a first test, Reader plus Cost Management Reader and Security Reader covers everything.

Flags
    

      
--subs ID,ID / --allScan these subscriptions, or every enabled one. With neither, the subscription of the current az login.

      
--regions a,bLimit to these regions (default: all).

      
--cloud NAMEAzureCloud or AzureUSGovernment. Default: detected from az cloud show, or AZURE_CLOUD.

      
--skip-vms, --skip-sql-mi, --skip-storage-accounts, --skip-files, --skip-backup, --skip-aks, --skip-cosmos-db, --skip-postgresqlPowerShell's -SkipAzureVMandManagedDisks, -SkipAzureSQLandMI, -SkipAzureStorageAccounts, -SkipAzureFiles, -SkipAzureBackup, -SkipAKS, -SkipAzureCosmosDB, -SkipAzurePostgreSQL. No prompt.

      
--no-cost, --no-capacity, --no-security, --no-backup-jobsSkip Cost Management, the storage metrics pass, Defender, or the backup job history.

      
--get-container-details, --get-key-vault-amountsOff by default, as in PowerShell (-GetContainerDetails, -GetKeyVaultAmounts): write azure_storage_account_container_info (needs Storage Blob Data Reader) or azure_key_vault (needs Key Vault Reader).

      
--no-devops, --devops-orgs a,bSkip Azure DevOps, or limit it to these organizations.

      
--anonymize [--anonymize-fields a,b] [--not-anonymize-fields a,b]Replace names, IDs and tags in the CSV files with labels. Tags in --not-anonymize-fields leaves tag columns alone. Not combinable with --no-csv.

      
--no-csv, --keep-artifactsJSON only; keep the loose JSON and log beside the zip.

      
--preflight-onlyOnly run the access check in each subscription and write azure_access_check_<timestamp>.zip with azure_preflight_check-<timestamp>.csv and the log. Nothing is collected. A subscription named with --subs that cannot be read gets a subscription row. Not with --no-csv or --mock.

      
--output DIR, --verbose, --mock, --config FILEOutput directory (default ~/clouddrive in Cloud Shell, else ./output); extra output; sample data; settings file (flags win).

    

  
The PowerShell script Get-AzureSizingInfo.ps1 remains the reference for output files. Flag mapping: docs/powershell-parameter-mapping.md.
